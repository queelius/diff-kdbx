# diff-kdbx 0.1 on kdbx-core: implementation plan

Spec: `~/github/kdbx/kdbx-core/docs/superpowers/specs/2026-10-18-kdbx-core-design.md`, section 4 (diff-kdbx) and section 6 (testing). The 2026-04-27 diff-kdbx spec remains the reference for motivation, textconv behavior, exit codes and the git-driver workflow; where the two disagree, the 2026-10-18 spec wins.

Context: diff-kdbx was never published. The local tags `v0.1.0`/`v0.2.0` and the branch `release/0.1` were release candidates for the old keepass-typed API and are retired by this work. The first crates.io release is 0.1.0 with the API below.

## Ground rules

- Branch `redesign/snapshot` from `main`. Depend on kdbx-core by path (`kdbx-core = { path = "../kdbx-core" }`) during development; the switch to a crates.io version happens at publish time.
- The library depends on kdbx-core only (no keepass). The `cli` feature enables `kdbx-core/keepass-0_15`, `kdbx-core/kdf`, and keepass 0.15 for opening files.
- Test-first per task, one conventional commit per task with the session trailers, no em-dash characters anywhere.
- `#[non_exhaustive]` on every public type that may grow; engine internals `pub(crate)`; the crate root re-exports the public API.
- Gates: `cargo fmt --check`; `cargo clippy --all-targets -- -D warnings`; `cargo clippy --all-targets --features cli -- -D warnings`; `cargo test --features cli`; `cargo test --lib`; `cargo build --target wasm32-unknown-unknown --no-default-features`; `cargo doc --no-deps --all-features` without warnings.

## Tasks

1. **Retarget the crate.** Version `0.1.0`, add `LICENSE` (MIT; the manifest already says MIT but the file is missing), dependency on kdbx-core, remove the direct keepass dependency from the library, feature wiring as above, `gen-fixtures` moved to `examples/gen_fixtures.rs` (with keepass `save_kdbx4` as a dev-dependency feature), `rust-version = "1.89"`. Old modules stay compiling behind the new skeleton only where needed; it is fine to delete code that the new design replaces. Commit.
2. **Properties.** `src/properties.rs`: `Property` (and nested key enums), `PropValue`, and `properties(&Meta)`, `properties(&Group)`, `properties(&Entry)` returning ordered `BTreeMap`s, derived from the kdbx-core model per spec 4.1. History items keyed by last-modification time with an index tiebreak. Unit tests: every model field maps to exactly one property (a test that builds an entry with every field set and asserts the property count, so a new model field without a property fails the test); ordering is deterministic. Commit.
3. **Change set.** `src/change_set.rs` rewritten per spec 4.2: `ChangeSet`, `Change`, `NodeChange`, `NodeStatus`, `PropertyChange`, `Shown`, `Summary` (every counter live, computed from changes), `DiffWarning` (KDBX version differs; remove `HashCollision`). Serde derives with the JSON shape described in 4.3. Commit.
4. **Compute.** `src/compute.rs` rewritten: match nodes by UUID across the two snapshots; per matched node, merge-join property maps; one record per node with `moved_from`; recycle-bin exclusion (ignoring a recycle-bin UUID that points at the root); noise suppression from `TimeField::is_noise` with counts in `Summary`; deterministic ordering (kind, path, UUID). Port every still-meaningful unit test from the old compute.rs; add the reviewer regression tests: moved-and-edited entry is one record and counts once; moved-and-renamed group is one record; protection toggle on an unchanged value is reported; override URL, autotype, custom data, colors (as `#RRGGBB`), icon, group notes/tags, and meta properties are reported; history trimmed at the cap and edited at the cap are reported as additions/removals; a recycle-bin UUID pointing at root does not hide the tree; `compute(a, a)` is empty. Commit.
5. **Dump.** `src/dump.rs` rewritten to print every node's properties in canonical order (spec 4.1), using `kdbx_core::text` for every value (continuation lines for multi-line values). `DumpOptions { noise, recycle_bin }` with the same semantics as diff (`--strict` shows noise in both). Test: every property `compute` can report appears in the dump (a structural test over a maximal fixture), and a value containing `"\n+ ENTRY /x"` cannot produce a line that starts like a structural line. Commit.
6. **Renderers.** Text renderer (tree-shaped, `kdbx_core::text` everywhere, fingerprints as 8 hex, sealed values as `<sealed:xxxxxxxx>`); JSON renderer with `format_version: 1`; `insta` snapshot tests for both over every fixture pair; remove `RenderOptions.color`. Commit.
7. **CLI.** Port `src/bin/diff-kdbx.rs` to: open with keepass 0.15; capture via `kdbx_core::keepass_0_15::capture` with `Sealing::Fingerprint` (key derived per spec 4.5) or `Sealing::Reveal` for `--show-secrets`; key-file-only vaults (empty interactive password with `--key-file` means no password; add `--no-password`); remove `--color`; add `diff-kdbx fingerprint --field <name> --entry <path-or-uuid> <vault>` that prints the keyed fingerprint (for verifying mcp-kdbx audit records later). Exit codes unchanged. Commit.
8. **Fixtures and integration tests.** Regenerate fixtures with `examples/gen_fixtures.rs` (fixed UUIDs, as today) and add pairs for the new cases (protected-title policy, multi-line notes injection, moved-and-edited, moved-and-renamed group, protection toggle, history at cap, override URL, recycle bin pointing at root, key-file-only vault). Port `tests/integration.rs`, `determinism.rs`, `git_driver.rs`, `remote_roundtrip.rs` to the new output; update expected strings deliberately. Add proptest: `compute(a, b)` and `compute(b, a)` are mirror images (added/removed swap, before/after swap). Commit.
9. **Public API review and docs.** Crate-root re-exports; rustdoc on every public item; README (usage, the JSON contract, sealing and fingerprints, how it differs from the existing `keepass-diff` crate), CLAUDE.md (new architecture and test counts), CHANGELOG rewritten (0.1.0 unreleased; note that the earlier local 0.1.0/0.2.0 candidates were never published). 10. **Retire the old release line.** After the branch merges to main (the owner or the orchestrating session does this, not the implementer): delete local tags `v0.1.0` and `v0.2.0` and the local branch `release/0.1`. Record this in the CHANGELOG.

## Decisions

Recorded while implementing (spec section 9 decisions take precedence; these cover what neither the plan nor the spec settles).

1. **Transitional legacy module (tasks 1 to 6).** Removing keepass from the library would leave the CLI and its 32 end-to-end tests without an engine until task 7. The old keepass-typed modules therefore move to `src/legacy/`, compiled only under the `cli` feature (where keepass is present anyway), so every commit passes every gate. Task 7 deletes them.
2. **kdbx-core dependency carries a version** (`path = "../kdbx-core", version = "0.1.0"`): Cargo uses the path locally and the version when packaging, so the switch to crates.io at publish time is a no-op.
3. **CI checks out kdbx-core as a sibling** (as mcp-kdbx does for diff-kdbx) and gains an MSRV (1.89.0) job and a rustdoc job.
4. **Argon2 opt-level overrides** move into this crate's manifest: profile settings in a dependency (kdbx-core) are ignored, and the CLI tests derive fingerprint keys.
5. **`PropValue` and `Shown` are one type, `Shown`.** The property map's value type is exactly what the change set carries and what the dump prints, so a second type would only be a parallel copy. `properties` returns `BTreeMap<Property, Shown>`.
6. **Property functions are `pub(crate)`** (spec 4.1 over the plan): `database_properties(&Snapshot)` (format, header, `<Meta>`, tombstones: the database level needs more than `Meta`), `group_properties(&Group)`, `entry_properties(&Entry)`.
7. **Key enums are typed, with one name each.** `FieldName { Standard(StandardField), Custom(String) }` orders the standard fields in KDBX order before custom fields. `TimeField`, `MetaKey`, `HeaderKey`, `GroupFlag`, `AutoTypeKey`, `ColorRole` carry their KDBX element names in a single `Display` match that `Serialize` reuses (`collect_str`), so the text label and the JSON key cannot drift.
8. **History items are flattened**: `Property::History { item: HistoryKey, property: Box<Property> }` for every property of every history item. One merge-join then reports added, removed and edited history items precisely, noise rules apply inside history unchanged, and the dump shows history contents. `HistoryKey { modified, index }` keys by last-modification time with a document-order index among equal times.
9. **Presence-valued keyed properties** (`Tag`, `PublicCustomData`, a tombstone without a time) take `Shown::Present`; Option-valued model fields are absent from the map when `None` (absent is "not set" or "inherited"), so a change from unset to set is an addition.
10. **`ExpiryTime` is a property only while the node expires** (`Expires == true`), the structural form of 0.2's rule that an inert expiry time is not reported.
11. **Noise is a typed classification** (`Property::is_noise`): the four noisy `TimeField`s, `GroupFlag::IsExpanded` (UI state), `PreviousParent` (restates a move), the custom-data and custom-icon modification times, tombstones (restate a removal), and the `MetaKey` application stamp, UI state and `*Changed` timestamps. `MasterKeyChanged` is not noise: it explains a wholesale fingerprint change.
12. **Coverage tripwire through serde.** kdbx-core's model structs are `#[non_exhaustive]`, so a downstream test cannot destructure them exhaustively. Instead, tests assert the serialized key set of each model struct, and mutate every JSON leaf of maximal values (deserializing back) to assert each one reaches the property map. A field kdbx-core adds later fails both.
13. **Summary counters**: added, removed, modified and moved for entries and for groups (moved is a subset of modified, so a moved-and-edited node counts once in each), node and database property-change counts, and `suppressed`. `ChangeSet::new(changes, warnings, suppressed)` is the only constructor and computes the rest, so no counter can be dead or stale.
14. **KDF weakening is a typed warning**: `DiffWarning::KdfWeakened { weakening: KdfWeakening }`, one warning per aspect: `NoLongerMemoryHard` (Argon2 to AES-KDF), `Unrecognized` (a recognized KDF replaced by one that cannot be assessed), `MemoryLowered`, `IterationsLowered`, `RoundsLowered`. Lowered Argon2 parallelism and an Argon2id/Argon2d switch are reported as header property changes but are not weakenings (neither lowers an attacker's cost). `VersionMismatch` carries typed `FormatVersion`s.
15. **JSON shape**: `Change` is tagged by `scope` (`database`, `group`, `entry`); node records flatten their status (`"status": "added" | "removed" | "modified"`, with `moved_from` and `changes` for `modified`); a missing side of a property change is an explicit `null`.
16. **Matching and moves.** Nodes match by UUID and kind (a UUID that changes kind is a removal plus an addition). A node moved when its parent group's UUID changed; `moved_from` is its old path. A node whose old path does not exist (an empty name on the way) and that moved still yields a `Modified` record, with `moved_from: None`; this edge is accepted rather than widening the spec's `Option<VaultPath>`.
17. **Each side uses its own recycle bin** (`meta.recycle_bin` of that snapshot), so trashing an entry reads as a removal by default and as a move with `--include-recycle-bin`. Paths come from `PathIndex::new` over the whole snapshot, so ordinals are the ecosystem's canonical ones whether or not the recycle bin is shown.
18. **Ordering** is (kind: groups before entries, path segment by segment with pathless nodes last, UUID), after the database record. Segment order (name, then ordinal) puts a group directly before its contents.
19. **Dump format.** `DATABASE`, then `GROUP <path> [uuid:<uuid>]` / `ENTRY <path> [uuid:<uuid>]` blocks in tree order (a group directly before its contents; `(no path)` for a pathless node), each followed by `  <label>: <value>` lines in canonical property order. The full UUID replaces 0.2's 8-character tag: paths are already unambiguous through ordinals, and the UUID is the identity a reader may need to look up. A presence-valued property prints as its label alone (`  Tag[finance]`). Multi-line properties (Notes by field trait, group Notes, the database description) print `  <label>:` and then one `    | <line>` per value line; any other value is escaped inline. History properties print flat (`  History[<time>].URL: ...`), one line per property, so a git diff of two dumps shows exactly the changed history lines.
20. **Value text forms**: sealed values `<sealed:xxxxxxxx>` (the fingerprint's short form); a protected plain value (a Title, or anything under `Sealing::Reveal`) gets ` (protected)`; a sealed but unprotected value (a Password whose flag is off) gets ` (unprotected)`; attachments `<sealed:xxxxxxxx> (N bytes[, protected])`; icons `standard N` / `custom <uuid>`; colors `#RRGGBB`. Paths render through `VaultPath::format`, which applies kdbx-core's escape core itself (passing a formatted path through `escape_inline` again would double every backslash and break `parse(format(p)) == p` for displayed paths).
21. **Text diff format.** `summary: entries +A/-R/~M (N moved), groups +A/-R/~M (N moved), properties P, database D, suppressed S` (label-value pairs, so no plural forms to get wrong); `warning: ...` lines; `(no changes)`; then `DATABASE` and `+`/`-`/`~` `GROUP`/`ENTRY` `<path>` records (`(moved from <path>)` on a move; `(no path) [uuid:...]` for a pathless node), with `  + label: value`, `  - label: value`, `  ~ label: before -> after` property lines. A modified multi-line value prints `  ~ label:` then its before lines as `      - | ...` and after lines as `      + | ...`. The diff shows no UUID for nodes with a path; the dump always does.
22. **JSON document**: `{"format_version": 1, "fingerprint_key": null | {"params": DeriveParams, "salt": uuid}, "changes", "summary", "warnings"}`, pretty-printed with a trailing newline. `render_json(&ChangeSet, &JsonOptions)` takes the fingerprint-key provenance as an option (`JsonOptions::with_fingerprint_key(FingerprintKeyInfo::new(params, salt))`) because the change set itself does not know how its snapshots were sealed; `JSON_FORMAT_VERSION` is a public constant.
23. **Snapshot tests cover every fixture pair** (text, JSON, and the after side's dump) plus the frozen KDBX 4.0 vault's dump, iterating the fixture directory so a new pair cannot be left out. They seal with a fixed `FingerprintKey::from_bytes([7; 32])`, so the committed fingerprints are stable without running the KDF.
24. **An empty text value keeps its colon** (`  Name:`); only presence-valued properties print a bare label.
25. **Task 7 ports the end-to-end expectations it breaks.** Porting the CLI changes every output string, so the existing integration tests are updated in the same commit (gates must pass at every commit); task 8 adds the new fixtures and their tests.
26. **Fingerprint key per CLI mode.** `--textconv`/`--dump`/`fingerprint`: derived per file from that file's key material, its root UUID as salt, and `DeriveParams::for_header(header(&db))`. Two-file diff: one key from side A's material and root UUID, with parameters the component-wise maximum of both vaults' `DeriveParams` (built with `DeriveParams::new` from the accessors, which re-applies the floor), so the key is never cheaper than either vault. `--show-secrets` still derives a key (`Sealing::Reveal` carries one for attachments and binary data). The JSON output records `params` and `salt`.
27. **Key resolution order**: `--no-password` (requires `--key-file`; overrides the environment), then `KDBX_DIFF_PASSWORD` (or `_A`/`_B`), then the TTY prompt (never in textconv; an empty answer with `--key-file` means no password), then a key file alone. Password and key-file bytes are held in `Zeroizing` buffers. A shared key that fails on B suggests `--separate-keys`.
28. **`diff-kdbx fingerprint --field NAME --entry PATH-OR-UUID [--key-file F] [--no-password] VAULT`** prints the full 64-hex `Domain::Field` fingerprint of the field's plaintext under the vault's own derived key (the key `--textconv` uses), so its first 8 characters match the dump's `<sealed:...>`. `--entry` is a UUID when it parses as one, otherwise a vault path resolved with `VaultPath::resolve_entry` (a group-shaped path is an error). It works for plain fields too.
