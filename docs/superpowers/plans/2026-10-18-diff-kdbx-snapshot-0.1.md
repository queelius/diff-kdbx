# diff-kdbx 0.1 on kdbx-core: implementation plan

Spec: `~/github/kdbx/kdbx-core/docs/superpowers/specs/2026-10-18-kdbx-core-design.md`, section 4 (diff-kdbx) and section 6 (testing). The 2026-04-27 diff-kdbx spec remains the reference for motivation, textconv behavior, exit codes and the git-driver workflow; where the two disagree, the 2026-10-18 spec wins.

Context: diff-kdbx was never published. The local tags `v0.1.0`/`v0.2.0` and the branch `release/0.1` were release candidates for the old keepass-typed API and are retired by this work. The first crates.io release is 0.1.0 with the API below.

## Ground rules

- Branch `redesign/snapshot` from `main`. Depend on kdbx-core by path (`kdbx-core = { path = "../kdbx-core" }`) during development; the switch to a crates.io version happens at publish time.
- The library depends on kdbx-core only (no keepass). The `cli` feature enables `kdbx-core/keepass-0_15`, `kdbx-core/kdf`, and keepass 0.15 for opening files.
- Test-first per task, one conventional commit per task with the session trailers, no em-dash characters anywhere.
- `#[non_exhaustive]` on every public type that may grow; engine internals `pub(crate)`; the crate root re-exports the public API.
- Gates: `cargo fmt --check`; `cargo clippy --all-targets -- -D warnings`; `cargo clippy --all-targets --features cli -- -D warnings`; `cargo test --features cli`; `cargo test --lib`; `cargo build --target wasm32-unknown-unknown --no-default-features`; `cargo doc --no-deps --all-features` without warnings.

## Decisions

Recorded while implementing (spec section 9 decisions take precedence; these cover what neither the plan nor the spec settles).

1. **Transitional legacy module (tasks 1 to 6).** Removing keepass from the library would leave the CLI and its 32 end-to-end tests without an engine until task 7. The old keepass-typed modules therefore move to `src/legacy/`, compiled only under the `cli` feature (where keepass is present anyway), so every commit passes every gate. Task 7 deletes them.
2. **kdbx-core dependency carries a version** (`path = "../kdbx-core", version = "0.1.0"`): Cargo uses the path locally and the version when packaging, so the switch to crates.io at publish time is a no-op.
3. **CI checks out kdbx-core as a sibling** (as mcp-kdbx does for diff-kdbx) and gains an MSRV (1.89.0) job and a rustdoc job.
4. **Argon2 opt-level overrides** move into this crate's manifest: profile settings in a dependency (kdbx-core) are ignored, and the CLI tests derive fingerprint keys.
5. **`PropValue` and `Shown` are one type, `Shown`.** The property map's value type is exactly what the change set carries and what the dump prints, so a second type would only be a parallel copy. `properties` returns `BTreeMap<Property, Shown>`.
6. **Property functions are `pub(crate)`** (spec 4.1 over the plan): `database_properties(&Snapshot)` (format, header, `<Meta>`, tombstones: the database level needs more than `Meta`), `group_properties(&Group)`, `entry_properties(&Entry)`.
7. **Key enums are typed, with one name each.** `FieldName { Standard(StandardField), Custom(String) }` orders the standard fields in KDBX order before custom fields. `TimeField`, `MetaKey`, `HeaderKey`, `GroupFlag`, `AutoTypeKey`, `ColorRole` carry their KDBX element names in a single `Display` match that `Serialize` reuses (`collect_str`), so the text label and the JSON key cannot drift.
8. **History items are flattened**: `Property::History { item: HistoryKey, property: Box<Property> }` for every property of every history item. One merge-join then reports added, removed and edited history items precisely, noise rules apply inside history unchanged, and the dump shows history contents. `HistoryKey { modified, index }` keys by last-modification time with a document-order index among equal times.
9. **Presence-valued keyed properties** (`Tag`, `PublicCustomData`, a tombstone without a time) take `Shown::Present`; Option-valued model fields are absent from the map when `None` (absent is "not set" or "inherited"), so a change from unset to set is an addition.
10. **`ExpiryTime` is a property only while the node expires** (`Expires == true`), the structural form of 0.2's rule that an inert expiry time is not reported.
11. **Noise is a typed classification** (`Property::is_noise`): the four noisy `TimeField`s, `GroupFlag::IsExpanded` (UI state), `PreviousParent` (restates a move), the custom-data and custom-icon modification times, tombstones (restate a removal), and the `MetaKey` application stamp, UI state and `*Changed` timestamps. `MasterKeyChanged` is not noise: it explains a wholesale fingerprint change.
12. **Coverage tripwire through serde.** kdbx-core's model structs are `#[non_exhaustive]`, so a downstream test cannot destructure them exhaustively. Instead, tests assert the serialized key set of each model struct, and mutate every JSON leaf of maximal values (deserializing back) to assert each one reaches the property map. A field kdbx-core adds later fails both.
13. **Summary counters**: added, removed, modified and moved for entries and for groups (moved is a subset of modified, so a moved-and-edited node counts once in each), node and database property-change counts, and `suppressed`. `ChangeSet::new(changes, warnings, suppressed)` is the only constructor and computes the rest, so no counter can be dead or stale.
14. **KDF weakening is a typed warning**: `DiffWarning::KdfWeakened { weakening: KdfWeakening }`, one warning per aspect: `NoLongerMemoryHard` (Argon2 to AES-KDF), `Unrecognized` (a recognized KDF replaced by one that cannot be assessed), `MemoryLowered`, `IterationsLowered`, `RoundsLowered`. Lowered Argon2 parallelism and an Argon2id/Argon2d switch are reported as header property changes but are not weakenings (neither lowers an attacker's cost). `VersionMismatch` carries typed `FormatVersion`s.
15. **JSON shape**: `Change` is tagged by `scope` (`database`, `group`, `entry`); node records flatten their status (`"status": "added" | "removed" | "modified"`, with `moved_from` and `changes` for `modified`); a missing side of a property change is an explicit `null`.
16. **Matching and moves.** Nodes match by UUID and kind (a UUID that changes kind is a removal plus an addition). A node moved when its parent group's UUID changed; `moved_from` is its old path. A node whose old path does not exist (an empty name on the way) and that moved still yields a `Modified` record, with `moved_from: None`; this edge is accepted rather than widening the spec's `Option<VaultPath>`.
17. **Each side uses its own recycle bin** (`meta.recycle_bin` of that snapshot), so trashing an entry reads as a removal by default and as a move with `--include-recycle-bin`. Paths come from `PathIndex::new` over the whole snapshot, so ordinals are the ecosystem's canonical ones whether or not the recycle bin is shown.
18. **Ordering** is (kind: groups before entries, path segment by segment with pathless nodes last, UUID), after the database record. Segment order (name, then ordinal) puts a group directly before its contents.
19. **Dump format.** `DATABASE`, then `GROUP <path> [uuid:<uuid>]` / `ENTRY <path> [uuid:<uuid>]` blocks in tree order (a group directly before its contents; `(no path)` for a pathless node), each followed by `  <label>: <value>` lines in canonical property order. The full UUID replaces 0.2's 8-character tag: paths are already unambiguous through ordinals, and the UUID is the identity a reader may need to look up. A presence-valued property prints as its label alone (`  Tag[finance]`). Multi-line properties (Notes by field trait, group Notes, the database description) print `  <label>:` and then one `    | <line>` per value line; any other value is escaped inline. History properties print flat (`  History[<time>].URL: ...`), one line per property, so a git diff of two dumps shows exactly the changed history lines.
20. **Value text forms**: sealed values `<sealed:xxxxxxxx>` (the fingerprint's short form); a protected plain value (a Title, or anything under `Sealing::Reveal`) gets ` (protected)`; a sealed but unprotected value (a Password whose flag is off) gets ` (unprotected)`; attachments `<sealed:xxxxxxxx> (N bytes[, protected])`; icons `standard N` / `custom <uuid>`; colors `#RRGGBB`. Paths render through `VaultPath::format`, which applies kdbx-core's escape core itself (passing a formatted path through `escape_inline` again would double every backslash and break `parse(format(p)) == p` for displayed paths).
21. **Text diff format.** `summary: entries +A/-R/~M (N moved), groups +A/-R/~M (N moved), properties P, database D, suppressed S` (label-value pairs, so no plural forms to get wrong); `warning: ...` lines; `(no changes)`; then `DATABASE` and `+`/`-`/`~` `GROUP`/`ENTRY` `<path>` records (`(moved from <path>)` on a move; `(no path) [uuid:...]` for a pathless node), with `  + label: value`, `  - label: value`, `  ~ label: before -> after` property lines. A modified multi-line value prints `  ~ label:` then its before lines as `      - | ...` and after lines as `      + | ...`. The diff shows no UUID for nodes with a path; the dump always does.
22. **JSON document**: `{"format_version": 1, "fingerprint_key": null | {"params": DeriveParams, "salt": uuid}, "changes", "summary", "warnings"}`, pretty-printed with a trailing newline. `render_json(&ChangeSet, &JsonOptions)` takes the fingerprint-key provenance as an option (`JsonOptions::with_fingerprint_key(FingerprintKeyInfo::new(params, salt))`) because the change set itself does not know how its snapshots were sealed; `JSON_FORMAT_VERSION` is a public constant.
23. **Snapshot tests cover every fixture pair** (text, JSON, and the after side's dump) plus the frozen KDBX 4.0 vault's dump, iterating the fixture directory so a new pair cannot be left out. They seal with a fixed `FingerprintKey::from_bytes([7; 32])`, so the committed fingerprints are stable without running the KDF.
24. **An empty text value keeps its colon** (`  Name:`); only presence-valued properties print a bare label.
25. **Task 7 ports the end-to-end expectations it breaks.** Porting the CLI changes every output string, so the existing integration tests are updated in the same commit (gates must pass at every commit); task 8 adds the new fixtures and their tests.
26. **Fingerprint key per CLI mode.** `--textconv`/`--dump`/`fingerprint`: derived per file from that file's key material, its root UUID as salt, and `DeriveParams::for_header(header(&db))`. Two-file diff: one key from side A's material and root UUID, with parameters `params_of(a).stronger(params_of(b))`: the costlier of the two vaults' `DeriveParams` by whole cost (memory x passes), so the key is never cheaper than either vault and never costlier than the stronger one (revised after review, see 34; the first version took a component-wise maximum). `--show-secrets` still derives a key (`Sealing::Reveal` carries one for attachments and binary data). The JSON output records `params` and `salt`.
27. **Key resolution order**: `--no-password` (requires `--key-file`; overrides the environment), then `KDBX_DIFF_PASSWORD` (or `_A`/`_B`), then the TTY prompt (never in textconv; an empty answer with `--key-file` means no password), then a key file alone. Password and key-file bytes are held in `Zeroizing` buffers. A shared key that fails on B suggests `--separate-keys`.
28. **`diff-kdbx fingerprint --field NAME --entry PATH-OR-UUID [--key-file F] [--no-password] VAULT`** prints the full 64-hex `Domain::Field` fingerprint of the field's plaintext under the vault's own derived key (the key `--textconv` uses), so its first 8 characters match the dump's `<sealed:...>`. `--entry` is a UUID when it parses as one, otherwise a vault path resolved with `VaultPath::resolve_entry` (a group-shaped path is an error). It works for plain fields too.
29. **Fixture KDF and times.** Every generated vault uses Argon2id 1 MiB / 2 passes / 1 lane, to keep both the vault's own unlock and the fingerprint key derivation (at the floor) fast in tests. The generator also now freezes entry creation times: 0.2's `stamp` preserved keepass's "now" creation time, so fixture dumps were not reproducible as the manifest claimed.
30. **New fixtures**: `move_and_edit`, `move_and_rename_group`, `history_at_cap` (cap 3, oldest trimmed by rebuilding `History`, since keepass 0.15 exposes only `add_entry`), `protected_title`, `notes_injection`, `protection_toggle`, `override_url`, `trash_entry` (a real recycle bin, removal by default and move with `--include-recycle-bin`), `recycle_bin_root`, `kdf_downgrade`, and the single-vault `keyfile_only` (vault plus published key file). Other properties (colors, icons, auto-type, custom data, group notes and tags, meta settings) are covered by unit tests on hand-built snapshots rather than more fixture pairs.
31. **The mirror property test lives in `tests/mirror.rs`** and uses only the public API (plus kdbx-core constructors): random trees over fixed UUID pools (same-named siblings, sealed and unprotected secrets, multi-line notes, tags, usage counts, either KDBX version), under both noise settings.
32. **The API pin is an integration test, not a doc test** (`tests/public_api.rs`; `cargo public-api` is not installed). It compiles from outside the crate, names every re-exported item, pins every function by `fn` pointer type, every struct field by type, and constructs every enum variant, so a rename, removal, signature or variant change fails to build; a doc test would do the same while cluttering the rendered docs. `HistoryKey::new` was added because a `#[non_exhaustive]` struct cannot be built outside the crate.
33. **Packaging** keeps `tests/fixtures/` and `tests/snapshots/` (so `cargo test` works from the tarball, as kdbx-core keeps its corpus) and excludes `.github/`, `CLAUDE.md`, `docs/superpowers/` and proptest regression files.
34. **Whole-cost key parameters (review fix).** kdbx-core's `DeriveParams` now compares whole cost (memory x passes) and offers `stronger`; the two-file diff uses `pa.stronger(pb)`. The per-component maximum it replaces could combine one vault's memory with the other's passes, deriving at a cost neither vault has (64 MiB x 50 passes for keepass-rs's default). A test with a vault above the floor in cost but below it in memory pins the new rule in both argument orders.
35. **Textconv output is treated as storable.** git's `cachetextconv` keeps textconv output as blobs under `refs/notes/textconv/<driver>`, which mirror pushes, mirror clones and `git bundle --all` carry. The docs make caching opt-in with that warning, `--show-secrets` with `--textconv` is a hard error (exit 2, checked before any file is opened), and the security notes state that every unsealed value (Notes especially) is plaintext metadata in dumps and diffs.
36. **CLI key handling (review fix).** `--separate-keys` with `--key-file` is refused (exit 2, pointing at `--key-file-a`/`--key-file-b`) instead of silently ignoring the shared key file. An empty `KDBX_DIFF_PASSWORD` (or `_A`/`_B`) together with a key file means "no password", the same rule as an empty interactive answer; without a key file it is an empty password. `main` runs the command under `catch_unwind` with a one-line panic hook, so any panic exits 2 (never 101); the wrapper is unit-tested in the binary rather than through a test-only trigger in production code.
37. **`fingerprint` subcommand (review fix, supersedes part of 28).** It captures with `Sealing::Fingerprint`: a secret field's sealed value already is the keyed fingerprint, and only a plain field is fingerprinted explicitly (same key, `Domain::Field`), so no plaintext secret is captured. `--params` takes `DeriveParams`' recorded (`Display`) form `argon2id$v=19$m=<KiB>,t=<passes>,p=<lanes>` and `--salt` a root-group UUID, so fingerprints recorded with other parameters or another vault's salt (a two-file diff's JSON, an mcp-kdbx audit log) can be reproduced. kdbx-core has no `FromStr` for `DeriveParams` (reported as a gap), so the binary parses exactly that grammar and rejects anything below the floor (`DeriveParams::new` would silently substitute the floor, and no fingerprint is ever derived with sub-floor parameters). The key material is always the opened vault's; the README states what can and cannot be verified, and that a two-file diff seals B's values with A's key.
38. **History pairing (review fix, refines 8).** `compute` no longer merge-joins history by per-side position. Within each group of history items sharing a modification time (or all lacking one), items equal in content pair first (the i-th equal item on each side) and report nothing, the rest pair by position, and leftovers are additions or removals; groups with different times never pair. Reported items are keyed `History[<time>#n]` where n numbers the reported items of the group, so the diff's `#n` need not equal an item's position in a dump (the dump keeps per-side positions). The rule is symmetric (the mirror property test holds). Remaining limitation: when one item is trimmed and another added within one shared time, the two pair by position and read as one item edited, since history items carry no identity of their own.
39. **API freeze (review fix).** Every enum variant that carries named fields is `#[non_exhaustive]` (`Change::Database`, `NodeStatus::Modified`, both `DiffWarning` variants, every `KdfWeakening` variant, `Shown::{Field, Attachment, Blob}`, `Property::{AutoTypeAssociation, History}`), so a field can be added without a breaking release; external code matches them with `..` and builds them with constructors (`Change::database`, `NodeStatus::modified`, `DiffWarning::{version_mismatch, kdf_weakened}`, `KdfWeakening::{no_longer_memory_hard, unrecognized, memory_lowered, iterations_lowered, rounds_lowered}`, `Shown::{field, attachment, blob}`, `Property::{auto_type_association, history}`). Single-value tuple variants stay open: their one value is the variant. `render_text` takes a `&TextOptions` (`#[non_exhaustive]`, `Default`, empty for now), so options can arrive later without a signature change.
40. **One reversible label and value grammar (review fix, supersedes the label syntax of 7 and the value forms of 19 to 21).** Closed-set names stay bare (standard field names, typed keys, UUIDs, timestamps, numbers, enum names, `<sealed:...>`, markers); every vault-controlled string printed next to renderer syntax is one `kdbx_core::text::quote` token: custom field labels (`"Tag[x]": ...`), the vault part of bracketed keys (`Tag["a]b"]`, `Attachment["n"]`, `CustomData["k"]`, `CustomData["k"].Modified`, `PublicCustomData["k"]`, `AutoType.Association["w"#2]`), plain single-line values (`URL: "b -> c"`, `Title: "Bank" (protected)`, including the empty value `Name: ""`), and node paths in record and block headers (`ENTRY "/Personal/Bank" [uuid:...]`, `(moved from "/Work/VPN")`). Paths were not in the review list but are vault strings beside renderer syntax: a title `VPN (moved from /Work/VPN)` would otherwise fake a move. A path token reads back with `unquote` then `VaultPath::parse`. Multi-line values keep continuation lines. Text diff and dump share `ValueText` and `Property`'s `Display`, so the grammar is identical in both. `src/render/grammar_tests.rs` scans rendered lines back (split at the first `: ` and ` -> ` outside quotes and brackets) for the reviewer's probes (a custom field named `  | forged notes line` or `History[2026-01-01T00:00:00Z].Password`, values `<sealed:2668135c>` and `a -> b`, tags containing `]`, a title imitating a move).
41. **The JSON wire format is owned by diff-kdbx (review fix, supersedes 15 and 22's leaf shapes).** Private wire types in `src/render/wire.rs` define every leaf (UUIDs, paths, timestamps via chrono with our own format string, 64-hex fingerprints, `#RRGGBB` colors, `"major.minor"` versions, and snake_case names for KDF kinds, ciphers, compression and auto-type obfuscation, with `"unrecognized"` for enum values a newer kdbx-core adds), so `format_version` 1 depends on no other crate's serde output. Envelopes are flattened: a field value is `{"type":"field","protected":b,"sealed":"<hex>"}` or `{...,"text":"..."}`; other scalars `{"type":T,"value":V}`; icons `{"type":"icon","standard":N}`/`{"custom":"<uuid>"}`; a history property `{"kind":"history","modified","index","property"}`; a KDF warning `{"kind":"kdf_weakened","aspect",...}`; format versions in warnings are strings. No public type implements `Serialize`; `render_json` is the one way to get JSON. Path strings use the ecosystem path grammar (spec 3.4), which is a cross-member contract by design rather than a serde representation. `chrono` (already in the graph through kdbx-core) becomes a direct dependency for the timestamp format.
42. **README for crates.io (review fix).** The install section is `cargo install diff-kdbx --features cli` (with a from-source note that checks out kdbx-core, to be created at github.com/queelius/kdbx-core, beside this repository), and links to files outside the package (`docs/superpowers/` is excluded) or to repository files point at GitHub URLs. The README also states that the KDF-weakening warning compares each parameter on its own (conservative, so lower memory warns even at equal total cost) while key derivation compares whole cost.
43. **Broader property and leak tests (review nits).** The mirror property test also generates history items (sharing, differing in or lacking modification times), a recycle bin (none, a group, or the root) and outer headers (AES-KDF and Argon2 parameter variations, an unrecognized KDF, two cipher sets); version-mismatch warnings must mirror, and KDF weakenings, being directional, must never name the same aspect in both directions. `tests/canary.rs` renders the text diff, the JSON and both dumps of every fixture pair (noise and recycle bin shown) and asserts that no secret appears, where the secrets are read from the vaults themselves (every field `is_secret` holds for, in entries and history, plus attachment contents) rather than listed by hand; a value one side holds as visible metadata (a field whose protection was turned off) is allowed in that side's dump and in the diff.
